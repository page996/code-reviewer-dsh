# 错误处理与失败语义

目标：失败必须可观测、可恢复、不放大影响面。

## 必查点
1. 吞异常：空 `catch {}`、`except: pass`、`catch (e) { return null }` 后继续执行，是否把错误伪装成成功。
2. 半途失败：多步写入/多资源操作缺少回滚或补偿；异常路径是否遗漏 `finally`/`defer`/`with` 清理。
3. 错误类型丢失：把原始错误降级为字符串或无上下文的新错误，导致调用方无法分支处理（尤其区分「不存在/冲突/超时」）。
4. 资源泄漏：文件句柄、连接、锁、临时目录、订阅在异常路径未释放。
5. 重试放大：对非幂等操作或 4xx 错误重试；无上限重试、无退避、重试风暴；重试未加取消/超时。
6. 超时与取消：外部调用没有超时；超时后仍继续提交结果；`AbortSignal`/`context` 未向下传递。
7. 失败开放：鉴权/校验出错时是否会「放行」；错误分支默认值是否比正常分支更宽松。
8. 错误信息：是否泄露内部路径、SQL、密钥、堆栈给终端用户（安全细节交给安全包）。

## 证据要求
- 指出可能抛错的调用点与吞错点（文件:行）。
- 给出触发异常的输入或依赖故障（超时、500、磁盘满、并发冲突）。
- 说明用户/调用方将观察到什么（成功假象、脏数据、挂起），以及正确失败语义。
- 如果调用方已在上层统一兜底，需给出该兜底代码位置，否则视为缺陷。

## 判定
- blocker：失败被伪装成功导致数据损坏；鉴权/校验错误时放行。
- major：错误不可恢复、资源泄漏、无上限重试。
- minor：错误上下文不足但仍有上层兜底。
