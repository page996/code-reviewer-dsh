# 测试有效性与回归覆盖

目标：判断新增/修改的测试是否真的能抓住这次改动引入的缺陷，而不是只增加行数。

## 必查点
1. 断言有效性：存在断言且断言的是行为/结果，不是「不抛异常」或只断言 mock 调用次数。
2. 覆盖改动分支：本次 diff 的错误分支、边界输入、权限分支是否有用例；只测 happy path 视为缺口。
3. 反向验证：测试在缺陷存在时是否会失败（可在脑中或 evidence 中说明构造的反例）。
4. 隔离与确定性：依赖真实网络/时间/随机/并发/外部服务的测试是否可控；固定 sleep 等待的脆弱测试。
5. Mock 滥用：过度 mock 把被测逻辑也 mock 掉；mock 返回值与真实契约不一致；断言 mock 实现细节导致重构即碎。
6. 回归用例：修复 bug 时是否补了能复现原缺陷的用例（缺陷输入 + 期望结果）。
7. 快照/黄金文件：快照是否覆盖关键语义、是否随手接受大范围变更；二进制/大快照的可维护性。
8. 初始化与清理：测试间共享状态、顺序依赖、未清理的临时文件/环境变量/数据库记录。
9. 跳过与隔离：`skip`/`only`/`xfail` 遗留、条件跳过把关键用例永久跳过。

## 证据要求
- 测试文件与行号；对应生产代码改动点。
- 说明哪个缺陷输入不会被现有断言捕获（给出具体输入）。
- 若认为缺失用例，描述应新增的最小用例与期望断言。
- 不因「测试写得少」本身扣分：必须绑定到本次 diff 的实际风险。

## 判定
- blocker：本次改动的高风险分支（鉴权/金额/数据删除）完全没有测试且无法用现有测试解释。
- major：关键错误路径/边界无用例，或测试断言无效。
- minor：存在脆弱/重复测试但不影响缺陷检出。
